## Playback cache and rendering improvements

- RAM-cached frames can be delivered while the video decoder is busy with another
  seek. Source, transport and request checks prevent older results replacing a newer hit.
- Prefetch continues during playback and fine scrubbing, follows the active range,
  and reserves space at the other end of a loop without increasing the cache budget.
- Compatible evicted GPU textures are recycled; repeated submissions of an unchanged
  frame avoid redundant rendering updates. Cache coverage updates skip unchanged data.
- Optional bounded diagnostics trace input, cache lookup, decoding, audio setup,
  texture uploads and Qt's presentation queue. Tracing is disabled by default.

Default budgets remain 512 MiB video RAM, 64 MiB GPU payload and 64 MiB audio.
There is no disk cache, proxy generation, or whole-video GPU preload.

## Results and remaining limits

Matched tests show faster cached delivery and successful texture recycling.
Cold 4K VP9 seeks and long sweeps remain variable and can still stutter; this
release does not establish a general cold-seek or CPU reduction. Hardware decoding
still downloads pixels to RAM before rendering uploads them. Audible scrubbing
can also stall during audio device setup. See the repository's
`docs/performance-playback-optimization-2026-10-27.md` for measurements and limitations.

## Install

Validation: all five native test suites passed (54 QtTest results including suite
setup/cleanup), along with the full native UI smoke test. Coverage includes source
changes, exact released frames, stale cache-hit ordering, blocked-decode cache
delivery, playback prefetch, loop-window limits, D3D11 colors/recycling, repeated
audio, timeline transport, bookmarks, exports, Cinema Mode and Always on Top.

Save your project and close FrameViewer, then run `TrieFrameViewer-Setup-1.4.0-x64.exe`.
Windows 10/11 x64 is required; runtime libraries and the exporter are included.
Downloads require an invited account for this private repository.
